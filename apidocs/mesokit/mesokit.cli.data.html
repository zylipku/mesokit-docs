mesokit.cli.data.list_() → None¶

List registered datasets, grouped by dynamics.

Datasets whose metadata.dyn matches a registered simulator are grouped under that dynamics name; user-registered datasets whose dyn is not a known simulator land in a trailing custom group. Use mesokit data avail to see the catalog of pre-defined simulator recipes.

A dataset is usable when its row reports yes; MISSING means the registry remembers a path that no longer resolves on disk.

mesokit.cli.data._available_impl() → None¶

List all pre-defined simulator recipes (catalog only, independent of registration).

Use mesokit data list for a per-dataset view of which recipes have actually been generated and registered.

Run a registered simulator, save the trajectories to HDF5, and register the result.

Registration is on by default. With no --name, the dataset is registered as <dyn>_v0 (or _v1, _v2, … — the next free slot — for repeated runs with different parameters). Pass --no-registry to skip registration entirely. --set key=value changes one recipe key without editing the YAML.

mesokit.cli.data.run_generate(dyn: str, *, config: str | None = None, name: str | None = None, output: pathlib.Path | None = None, register: bool = True, force: bool = False, verbose: bool = False, overrides: collections.abc.Mapping[str, Any] | None = None) → mesokit.cli.data.GenerateResult¶

Core of mesokit data generate, shared with mesokit sweep and callable from Python.

Loads configs/data/<dyn>/<config>.yaml (default default), applies overrides (simulator kwargs; unknown keys are rejected before the simulator runs), instantiates the simulator, saves the dataset to output (default data/<dyn>/<name>.h5) and, when register is true, validates and registers it under name (default the next free <dyn>_v<n>). report is None when nothing was registered.

mesokit.cli.data.parse(file: Annotated[pathlib.Path, typer.Option('--file', help='Input dataset to convert (any format).')], output: Annotated[pathlib.Path | None, typer.Option('--output', help='HDF5 path to write. Defaults to data/parsed/<stem>.h5.')] = None, hint: Annotated[str | None, typer.Option('--hint', help="Extra instructions for the agent (e.g. 'time dim is t, var is u').")] = None, agent: Annotated[str, typer.Option('--agent', help=_AGENT_HELP)] = 'claude', backend: Annotated[str, typer.Option('--backend', help=_BACKEND_HELP)] = 'foreground', name: Annotated[str | None, typer.Option('--name', help='If given, register the produced HDF5 under this name on success.')] = None, force: Annotated[bool, typer.Option('--force', help='Overwrite an existing registry entry.')] = False) → None¶

Hand off conversion of an arbitrary dataset to an LLM agent.

The agent (claude, codex, …) is launched in the chosen backend (foreground blocks and streams; tmux detaches into a session) and pointed at the shipped mesokit-convert-data skill plus the user’s file. On return, the produced HDF5 is validated; with --name it is also registered, matching mesokit data generate.
