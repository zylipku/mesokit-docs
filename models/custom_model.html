Custom Models¶

You extend mesokit from your own module, never by editing src/mesokit/. Put the module in plugins/ in the directory you run mesokit from (the checkout for extension work — the folder is gitignored — or any project directory): every mesokit command imports what it finds there, so a model registered by name through mesokit.models.register is available to --model like a shipped one, and a recipe can name the class by _target_. From Python, import the module yourself before calling anything by name.

With the module in plugins/, mesokit train --model <registered name> works exactly as for a shipped family: the registry supplies the class, the grid is filled from the dataset, and the shipped LitTrainer trains it unless you register or name a trainer of your own. No recipe is needed; --set adjusts the constructor arguments. A recipe may instead name the class by model._target_ (then registration is optional), and mesokit interpret rebuilds the checkpoint from the saved recipe either way. The end-to-end flow is at the bottom of this page; the same works from Python as shown in Training.

Reuse Before Writing¶

Most “new model” needs are a new component of a shipped family, which keeps the family’s stepper, trainer and potential artifact:

The shipped implementations are the reference: mesokit.models.fno (rhs plus explicit stepper around an external operator), mesokit.models.onsagernet (rhs with autograd, pluggable blocks), mesokit.models.spectral_onsagernet (custom forward in Fourier space, pluggable potentials).

The DynamicsModel Protocol¶

A model is any torch.nn.Module that structurally satisfies mesokit.models.DynamicsModel: forward(u, dt) advances one step, rollout(u0, n_steps, dt) iterates it, list_artifacts() names at least one interpretability artifact, and artifact(name) builds it. Tensors carry a leading batch dimension; the stock training views slice one channel and feed (B, *grid_shape) — (B, Nx) for 1D data, (B, Nx, Ny) for 2D — so a model declares which grids it accepts through its constructor (the shipped families are registered once per dimension: fno1d / fno2d / fno3d, spectral_onsagernet_1d / _2d / _3d, onsagernet_1d / _2d / _3d). The protocol is structural (typing.Protocol); no inheritance is required, and isinstance(model, DynamicsModel) checks it at runtime.

Two implementation patterns cover the shipped families. The simplest is a right-hand side plus one of the shared explicit steppers:

# plugins/my_models.py
import torch
from torch import Tensor, nn
from torch.nn import functional as F

from mesokit.models import euler_step, register, rollout


@register("linear_decay_1d")
class LinearDecay1d(nn.Module):
    """du/dt = -softplus(rate) * u with a single learnable scalar."""

    def __init__(self, Nx: int = 64) -> None:
        super().__init__()
        self.Nx = Nx
        self.rate = nn.Parameter(torch.tensor(0.0))

    def rhs(self, u: Tensor) -> Tensor:
        return -F.softplus(self.rate) * u

    def forward(self, u: Tensor, dt: float) -> Tensor:
        return euler_step(self.rhs, u, dt)

    def rollout(self, u0: Tensor, n_steps: int, dt: float) -> Tensor:
        return rollout(self.forward, u0, n_steps, dt)

    def list_artifacts(self) -> list[str]:
        return ["rate"]

    def artifact(self, name: str):
        if name not in self.list_artifacts():
            raise KeyError(f"unknown artifact {name!r}; available: {self.list_artifacts()}")
        from my_artifacts import ScalarArtifact

        return ScalarArtifact(
            model_name="linear_decay_1d",
            dyn_name="decay_1d",
            artifact_name=name,
            value=float(F.softplus(self.rate)),
        )

ScalarArtifact is the minimal artifact class from Custom Artifacts. mesokit.models.rk4_step is the other stock stepper.

Models that need an operator between time slices or an implicit / spectral scheme implement forward directly instead; SpectralOnsagerNet in the API reference is the shipped example. Validate the trailing shape in forward and raise a clear ValueError on a mismatch — that is the error users hit most.

Writing Once for 1D, 2D and 3D¶

mesokit.models._spectral.SpectralGrid(grid_shape, domain) gives you the wavenumbers, transforms and cell volume for any periodic box, so the same code serves every dimension: rfft(u) / irfft(u_hat) over the trailing axes, per-axis wavenumbers(), k_squared(), gradient(u), integrate(density), cell_volume, the truncate(u_hat, n_modes) helper used by nonlocal potentials, and the de-aliasing pair pad_spectrum(u_hat, factor) / truncate_spectrum(w_hat, factor) (with refined(factor) for the fine grid and zero_nyquist(u_hat) for the symmetric band). Grids must be even along every axis. The shipped families keep a dimension-agnostic core taking grid_shape / domain tuples plus thin registered shells (Nx, Lx → Nx, Ny, Lx, Ly); that convention makes a new family usable in every dimension with no FFT code of its own.

Two more conventions worth keeping: enforce structure by parameterisation (squares, softplus, antisymmetric construction), not by penalty; and take gradients of a learned potential by autograd inside rhs, wrapped in torch.inference_mode(False) and torch.enable_grad() so evaluation loops that run under inference mode still work.

Checking Before Training¶

# check_model.py
import torch

import my_models  # registers
from mesokit.models import DynamicsModel, available

model = my_models.LinearDecay1d(Nx=64)
assert isinstance(model, DynamicsModel)
assert "linear_decay_1d" in available()
u = torch.randn(4, 64)
assert model(u, 1e-2).shape == u.shape
assert model.rollout(u, 3, 1e-2).shape == (4, 4, 64)

Training It Through the CLI¶

With plugins/my_models.py in place, the registered name is enough:

mesokit train --model linear_decay_1d --data decay_1d_v0 --set trainer.max_epochs=50
mesokit interpret extract --model linear_decay_1d_v0 --artifact rate --output figs/rate.png

Nx is filled from the dataset, LitTrainer is the trainer, and --set changes anything else. To keep a configuration, or to use a class without registering it, write a recipe under configs/train/<dyn>/<model name>/default.yaml whose model section names the class:

# configs/train/decay_1d/linear_decay_1d/default.yaml
model:
  _target_: my_models.LinearDecay1d      # Nx is filled from the dataset (the constructor accepts it)

dataset:
  _target_: mesokit.data.datasets.snapshot_pair_dataset.SnapshotPairDataset
  stride: 1

dataloader:
  batch_size: 32
  shuffle: true
  num_workers: 0

trainer:
  _target_: mesokit.trainers.lit_trainer.lit_trainer.LitTrainer
  max_epochs: 50
  lr: 1.0e-2
  dt: null
  accelerator: cpu

mesokit train --model linear_decay_1d --data decay_1d_v0

The shipped LitTrainer trains any DynamicsModel; a trainer of your own goes into trainer._target_ the same way, or is registered under the model name (Custom Trainers). If the module is not under plugins/ (nor installed), Hydra cannot import the class and the command fails naming the module. The same model trains from Python as shown in Training.
