# Agent Skills

You can ask a coding agent to help convert data, train a model, or add a
custom extension. `mesokit` includes six skills: task guides that the
agent reads to carry out these workflows using mesokit's commands and
Python API.

Skills are optional. You can follow the same workflows yourself through
the [Quickstart](quickstart.md) and the rest of this guide.

## Set up your project

Install a supported coding agent using its official instructions:
[Claude Code](https://code.claude.com/docs/en/setup) or
[Codex CLI](https://developers.openai.com/codex/cli).
See {ref}`how to use CLI <running-the-cli>`.

From your project directory, set up the agent you use:

```console
$ mesokit agent init --agent claude
```

For Codex, use `--agent codex`; for both, use `--agent both`. This writes
project guidance and installs the skills in the appropriate project
folders. Start your agent from that same directory so it can find your
recipes and registered datasets.

See [`mesokit agent`](cli/agent.md) for the files created and how existing
guidance is preserved. In the mesokit checkout, project guidance is
already present; use `mesokit skills install --agent codex` to install
project skills for Codex.

## Choose a task

Describe your task in ordinary language and include the files, dataset
names, or checkpoints you want to use. You can also name a skill
explicitly; in Claude Code, for example, use `/mesokit-train`.

| Skill | Use it to | Typical result |
| --- | --- | --- |
| `mesokit-convert-data` | Import an existing file such as `.npz`, `.nc`, `.pt`, or a foreign HDF5 file | A validated mesokit HDF5 file, optionally registered by name |
| `mesokit-add-simulator` | Generate data from your own equation or solver | A simulator module and a data recipe, checked on a small run |
| `mesokit-train` | Fit a model and inspect what it learned | A training recipe, checkpoint, and interpretation of its artifacts |
| `mesokit-add-model` | Add a model or a component such as a potential or mobility operator | A Python extension checked for shapes, gradients, and training compatibility |
| `mesokit-add-trainer` | Use a different objective or training loop | Trainer settings or a custom trainer, checked on a small run |
| `mesokit-add-artifact` | Read a new diagnostic from a trained model | An artifact with a summary and figure, optionally compared with existing artifacts |

## Example requests

**Convert existing data:**

> I have `runs/burgers.npz` with `u` shaped (200, 101, 256) and a time
> array `t`. The axes are trajectory, time, and position; the domain is
> [0, 2π), periodic. Import it as `burgers_v0`.

The agent inspects the file, writes the HDF5 cache, validates it, and
registers the requested name. If essential metadata is missing, it asks
for that information.

**Train and interpret:**

> Train Spectral OnsagerNet on `burgers_v0`. Start with a short CPU run,
> then show me the loss curve and explain the learned potential.

The agent checks the data and training settings, runs a small fit, and
uses the checkpoint's artifacts to describe what the model learned.

**Add your own solver:**

> My `heat_1d.py` solves the heat equation on a periodic grid. Make it
> available through `mesokit data generate` and check that the generated
> trajectories conserve the spatial mean.

The agent creates an extension in your project and a matching recipe.
See [Custom Simulators](data_processing/custom_simulator.md) for the
interface used by this workflow.

**Add a diagnostic:**

> From checkpoint `son_demo`, plot the learned mobility against squared
> wavenumber and compare it with the `potential` artifact.

The agent can compute this from the saved model and create a figure
without changing the model itself; see
[Custom Artifacts](interpretability/custom_artifact.md).

## What to expect

The agent runs commands and writes files in your project: data under
`data/`, trained runs under `checkpoints/`, and figures under `figs/`.
Extensions go in your own Python modules, usually under `plugins/`, and
reusable settings go under `configs/`.

The skills start with small runs and include checks before reporting
results. Validation confirms the file format; it does not establish that
the data or learned model is physically correct. Review the reported
assumptions, metrics, and plots when deciding what to run next.

## Convert a file directly from the command line

`mesokit data parse` launches an installed agent for a single conversion,
then validates the output and optionally registers it:

```console
$ mesokit data parse \
  --file runs/field.nc \
  --hint "variable phi, dimensions (member, time, x)" \
  --name phi_v0
```

To try it with a supplied practice file:

```console
$ mesokit data demo
$ mesokit data parse --file data/demo/allen_cahn_1d_demo.npz --name ac_imported
```

This runs without an interactive conversation. The command prints the
agent invocation, including its permissions. See
{ref}`mesokit data parse <mesokit-data-parse>` for agent selection,
output paths, and foreground or detached execution.

## Inspect or refresh installed skills

```console
$ mesokit skills list
$ mesokit skills path mesokit-train
$ mesokit skills install --agent codex --force
```

Installed skills are copies of the version bundled with mesokit. Refresh
them after upgrading and start a new agent session. If you also want to
refresh the project's mesokit guidance, use
`mesokit agent init --agent codex --force`.

[`mesokit skills`](cli/skills.md) covers installing selected skills,
user-wide installation, and custom destination folders.
