# Versioning and Compatibility

The trajectory cache format is versioned by integer. The version a file
declares is the only authoritative source of its shape and semantics:
readers should branch on the `version` root attribute, never on the
filename or directory.

## The Current Version

The current schema is **v1** — defined by
{py:data}`mesokit.data.format.TRAJECTORY_CACHE_V1` and re-exported as
{py:data}`mesokit.data.format.CURRENT_TRAJECTORY_CACHE_FORMAT`. Files
produced by `mesokit data generate` and by the in-Python helper
`TrajectoryDataset.save_hdf5` both stamp `format = "mesokit-trajectory"`
and `version = 1` at the file root.

The [Data Structure](structure.md) page is the reference for v1's layout
and the validator's checks.

## What v1 Guarantees

The v1 compatibility promise is path- and shape-based:

- `data` and `times` keep their top-level names and required dtypes.
- `data` keeps the axis order `(n_traj, n_time, n_channel, *grid_shape)`.
- `times` keeps the shape `(n_time,)`.
- The root attributes `format`, `version`, `dyn`, `data_dtype` keep their
  meanings and remain required.
- The three metadata groups (`physical/`, `numerical/`, `provenance/`)
  keep their names and open-content semantics.
- Unknown entries inside the metadata groups are allowed and round-trip
  transparently through `validate` and `TrajectoryDataset.load_hdf5`.

A file that satisfies all of the above today will satisfy `validate(path)`
for the entire lifetime of v1.

When a future schema version ships, the v1 constant stays available so
existing v1 files continue to load; no file ever auto-migrates at read
time.

## Reserved Names

When writing your own metadata, avoid two reserved namespaces — they are
held back for format markers added in later versions:

- Root attributes beginning with `mesokit_`.
- Group keys beginning with `_` (a single underscore).

Use ordinary names like `eps`, `Lx`, or a project-specific prefix for
your domain parameters.
