# Extending mesokit

mesokit is built around four small structural protocols and three name
registries. You extend it from **your own module**, never by editing
`src/mesokit/`, and the toolkit picks your pieces up by name. This page is
the public contract for each extension point plus a minimal working example
you can copy.

## Where extensions live

- Put your code in a module the `mesokit` process can import: a package
  installed into the pixi environment, or a directory on `PYTHONPATH`.
- Registries are populated by *import*. Import your module (or run it as a
  script) before calling anything by name.
- Config entries for your own dynamics (`configs/data/<dyn>/`,
  `configs/train/<dyn>/<model>/`) sit beside the shipped ones; see
  "Config conventions" below.

What each extension point can reach today:

| Extension | Python API | CLI |
| --- | --- | --- |
| Simulator | `mesokit.data.register`, then `simulate(name, ...)` | `mesokit data generate --dyn <dyn>` through a Hydra `_target_` in `configs/data/<dyn>/default.yaml` |
| Model | `mesokit.models.register`, then any trainer | Not yet: `mesokit train` only resolves architectures the installed package registered |
| Trainer | `mesokit.trainers.register_trainer`, then `.fit(...)` | Not yet, same reason |
| Artifact | returned by your model's `artifact(name)` | Not yet: `mesokit interpret` needs the model in the registry |

Loading user modules from the CLI is on the roadmap. Until then, train and
interpret custom models from Python as in the end-to-end example at the
bottom of this page. Built-in models on your own data already work end to
end through the CLI.

## Custom simulator

A simulator is any **keyword-only** callable that returns a
`TrajectoryDataset`. It must accept `verbose: bool = False` (the CLI
forwards `--verbose` through it) and should echo its identifying parameters
into the three metadata groups so the file is self-describing.

```python
# my_sims.py
import numpy as np
import torch

from mesokit.data import TrajectoryDataset, register


@register("decay_1d")
def simulate_decay_1d(
    *,
    n_traj: int = 8,
    Nx: int = 64,
    T: float = 1.0,
    n_time: int = 21,
    rate: float = 1.0,
    seed: int = 0,
    verbose: bool = False,
) -> TrajectoryDataset:
    """Every trajectory decays exponentially from a random initial field."""
    rng = np.random.default_rng(seed)
    times = np.linspace(0.0, T, n_time)
    u0 = rng.standard_normal((n_traj, 1, Nx))  # (n_traj, n_channel, Nx)
    data = u0[:, None] * np.exp(-rate * times)[None, :, None, None]
    return TrajectoryDataset(
        data=torch.as_tensor(data, dtype=torch.float32),  # (n_traj, n_time, 1, Nx)
        times=torch.as_tensor(times, dtype=torch.float32),
        dyn="decay_1d",
        physical={"T": T, "rate": rate},
        numerical={"Nx": Nx, "dt": T / (n_time - 1)},
        provenance={"seed": seed, "generator": "my_sims.simulate_decay_1d"},
        channel_names=("u",),
    )
```

From Python, dispatch by name and save the v1 cache file:

```python
# save_decay.py
from pathlib import Path

import my_sims  # noqa: F401  (registers "decay_1d")
from mesokit.data import simulate

ds = simulate("decay_1d", n_traj=4)
out = Path("data/decay_1d/decay_1d_v0.h5")
out.parent.mkdir(parents=True, exist_ok=True)
ds.save_hdf5(out)
```

From the CLI, point a Hydra config at your callable and make sure your
module is importable in the `mesokit` process:

```yaml
# configs/data/decay_1d/default.yaml
_target_: my_sims.simulate_decay_1d
n_traj: 8
Nx: 64
T: 1.0
n_time: 21
rate: 1.0
seed: 0
```

```sh
PYTHONPATH=. mesokit data generate --dyn decay_1d      # writes + registers decay_1d_v0
```

`mesokit data list` shows the dataset under `custom:` because the CLI
process never imported `my_sims`; everything downstream works regardless.
Validation and registration of files you wrote some other way are covered in
[Custom Datasets](data_processing/custom.md).

## Custom model

A model is any `torch.nn.Module` that structurally satisfies
`mesokit.models.DynamicsModel`: `forward(u, dt)` advances one step,
`rollout(u0, n_steps, dt)` iterates it, `list_artifacts()` names at least
one interpretability artifact, and `artifact(name)` builds it. Tensors carry
a leading batch dimension; the stock training views slice one channel and
feed `(B, *grid_shape)` — `(B, Nx)` for 1D data, `(B, Nx, Ny)` for 2D — so
a model declares which grids it accepts through its constructor (the
shipped families are registered once per dimension: `fno1d` / `fno2d` /
`fno3d`, `spectral_onsagernet_1d` / `_2d` / `_3d`, `onsagernet_1d` / `_2d` /
`_3d`).

Two implementation patterns cover the shipped families. The simplest is a
right-hand side plus one of the shared explicit steppers:

```python
# my_models.py
import torch
from torch import Tensor, nn
from torch.nn import functional as F

from mesokit.models import euler_step, register, rollout


@register("linear_decay_1d")
class LinearDecay1d(nn.Module):
    """du/dt = -softplus(rate) * u with a single learnable scalar."""

    def __init__(self, Nx: int = 64) -> None:
        super().__init__()
        self.Nx = Nx
        self.rate = nn.Parameter(torch.tensor(0.0))

    def rhs(self, u: Tensor) -> Tensor:
        return -F.softplus(self.rate) * u

    def forward(self, u: Tensor, dt: float) -> Tensor:
        return euler_step(self.rhs, u, dt)

    def rollout(self, u0: Tensor, n_steps: int, dt: float) -> Tensor:
        return rollout(self.forward, u0, n_steps, dt)

    def list_artifacts(self) -> list[str]:
        return ["rate"]

    def artifact(self, name: str):
        if name not in self.list_artifacts():
            raise KeyError(f"unknown artifact {name!r}; available: {self.list_artifacts()}")
        from my_artifacts import ScalarArtifact

        return ScalarArtifact(
            model_name="linear_decay_1d",
            dyn_name="decay_1d",
            artifact_name=name,
            value=float(F.softplus(self.rate)),
        )
```

Models that need an operator between time slices or an implicit / spectral
scheme implement `forward` directly instead; `SpectralOnsagerNet` in the
API reference is the shipped example, and
`mesokit.models._spectral.SpectralGrid` gives you the wavenumbers,
transforms and cell volume for any periodic box so the same code serves 1D,
2D and 3D. `mesokit.models.rk4_step` is the other stock stepper. See
[Models](models.md) for what the shipped families compute.

## Custom trainer

A trainer is anything with
`fit(model, train_loader, val_loader=None) -> TrainResult`. It owns the
training loop and writes the canonical Lightning-free `model.pt`
state-dict; registry bookkeeping is done by the CLI, so `fit` is safe to
call from a notebook. Register it under the model name it is the default
for. The stock choice is `mesokit.trainers.LitTrainer`, and
`mesokit.data.datasets` ships `SnapshotPairDataset` (adjacent-step pairs)
and `LookbackWindowDataset` as ready-made training views; any
`torch.utils.data.DataLoader` is accepted.

```python
# my_trainer.py
from pathlib import Path

import torch
from torch import nn, optim
from torch.nn import functional as F
from torch.utils.data import DataLoader

from mesokit.trainers import TrainResult, register_trainer


@register_trainer("linear_decay_1d")
class PlainTorchTrainer:
    """Minimal next-step MSE loop without Lightning."""

    def __init__(
        self,
        *,
        epochs: int = 50,
        lr: float = 1e-2,
        dt: float = 0.05,
        checkpoint_root: str | Path = "checkpoints/decay_1d",
        run_id: str = "plain",
    ) -> None:
        self.epochs, self.lr, self.dt = epochs, lr, dt
        self.checkpoint_root, self.run_id = Path(checkpoint_root), run_id

    def fit(self, model: nn.Module, train_loader: DataLoader, val_loader: DataLoader | None = None) -> TrainResult:
        optimizer = optim.Adam(model.parameters(), lr=self.lr)
        history: dict[str, list[float]] = {"train_loss": []}
        for _ in range(self.epochs):
            total = 0.0
            for u_t, u_next in train_loader:
                loss = F.mse_loss(model(u_t, self.dt), u_next)
                optimizer.zero_grad()
                loss.backward()
                optimizer.step()
                total += loss.item()
            history["train_loss"].append(total / len(train_loader))
        run_dir = self.checkpoint_root / self.run_id
        run_dir.mkdir(parents=True, exist_ok=True)
        checkpoint_path = run_dir / "model.pt"
        torch.save(model.state_dict(), checkpoint_path)
        return TrainResult(model=model, checkpoint_path=checkpoint_path, run_id=self.run_id, history=history)
```

## Custom artifact

An artifact is whatever your model returns from `artifact(name)`. The
comparison harness (`mesokit.interpret.compare`) relies only on the
`mesokit.interpret.InterpretabilityArtifact` surface: three labels,
`summary()`, `plot(ax=None)`, and `save(path)`. Anything else (a sympy
expression, a potential on a grid, a spectrum) is yours to add. Keep the
artifact class next to the model that builds it.

```python
# my_artifacts.py
from dataclasses import dataclass
from pathlib import Path
from typing import Any

import matplotlib.pyplot as plt

from mesokit.interpret import repr_html_summary


@dataclass
class ScalarArtifact:
    model_name: str
    dyn_name: str
    artifact_name: str
    value: float

    def summary(self) -> str:
        return f"{self.model_name} on {self.dyn_name}: learned {self.artifact_name} = {self.value:.4g}"

    def plot(self, ax: Any | None = None) -> Any:
        if ax is None:
            _, ax = plt.subplots()
        ax.bar([self.artifact_name], [self.value])
        ax.set_title(self.summary())
        return ax.figure

    def save(self, path: str | Path, **kwargs: Any) -> Path:
        fig = self.plot()
        fig.savefig(path, **kwargs)
        plt.close(fig)
        return Path(path)

    def _repr_html_(self) -> str:  # optional notebook display
        return repr_html_summary(self)
```

## Config conventions

Configs are Hydra YAML files and the CLI reads them from the current
working directory, so run commands from the repository root.

- `configs/data/<dyn>/default.yaml` is the recipe `mesokit data generate
  --dyn <dyn>` uses; sibling files are variants selected by stem with
  `--config <stem>`. The `_target_` may be any importable callable that
  satisfies the simulator contract.
- `configs/train/<dyn>/<model>/<stem>.yaml` drives `mesokit train`. It has
  four sections: `model` (constructor kwargs; `_target_` defaults to the
  registered class), `dataset` (the `TrajectoryDataset` wrapper, e.g.
  `SnapshotPairDataset` with `stride`), `dataloader`, and `trainer`
  (hyperparameters; `dt: null` means "infer from the data").
- A built-in model on your own dynamics needs its own train config. Copy
  `configs/train/allen_cahn_1d/spectral_onsagernet_1d/default.yaml` to
  `configs/train/decay_1d/spectral_onsagernet_1d/default.yaml`, set `Nx` to
  your grid size, then:

```sh
mesokit train --model spectral_onsagernet_1d --dyn decay_1d --data decay_1d_v0 --epochs 5 --device cpu
```

## End to end from Python

Everything above, without the CLI: simulate, wrap, train, interpret.

```python
# run_decay.py
import my_artifacts  # noqa: F401
import my_models
import my_sims  # noqa: F401
import my_trainer
from torch.utils.data import DataLoader

from mesokit.data import simulate
from mesokit.data.datasets import SnapshotPairDataset

ds = simulate("decay_1d", n_traj=8, Nx=64, T=1.0, n_time=21, rate=0.7)
loader = DataLoader(SnapshotPairDataset(ds), batch_size=32, shuffle=True)

model = my_models.LinearDecay1d(Nx=ds.grid_shape[0])
trainer = my_trainer.PlainTorchTrainer(epochs=200, lr=5e-2, dt=float(ds.numerical["dt"]))
result = trainer.fit(model, loader)

artifact = model.artifact("rate")
print(artifact.summary())  # learned rate close to 0.7
print(result.checkpoint_path, result.history["train_loss"][-1])
artifact.save("figs/decay_rate.png")
```

Swap `PlainTorchTrainer` for `mesokit.trainers.LitTrainer(max_epochs=...,
dt=...)` to get Lightning's checkpointing and `history.json` for free; the
`fit` call is identical.
